# 研究任务试用记录

[English](README.en.md)

这些是本轮开发中的独立代理试用与实际 CPU 产物，用来判断回答是否有用、寻找改进点。它们不是重复采样的盲评，没有经过可信运行时适配器采集，不计入 Tier 2 行为通过率。文件读取清单由执行代理自报。测试资料不进入 npm 发布包。

## 跨数学领域探索

给一个独立代理当前 skill 和以下请求，没有提供预期数学路线，也没有让它读取已有试用答案：

> 我想研究一种在线信息融合模块：同一批观测换个到达顺序，最终结果应该一样；每次只能增量更新，不能保存全部原始历史；相互矛盾的观测又不应该被平均成一个看似确定的结论。请从不同数学领域寻找两条结构上真正不同的研究思路，说明为什么有价值、关键对应是什么、哪种情况会失败。不要从现成 attention 或 routing 模板开始，也暂时不用写训练代码。

完整[研究回答](runs/transfer-answer.md)与[资源访问自报](runs/transfer-access.md)保留供人工判断。代理读取了主入口和结构迁移说明，检索了题目所需来源，没有读取设计原型或迁移桥示例。

回答提出了两种不同的信息语义：

| 方向 | 数学对应及保证 | 代价与失效情形 |
|---|---|---|
| 四值证据格 | 正负证据对应两个比特，逐位 OR 融合；交换、结合、幂等；区分未知与冲突 | 固定命题词表；错误证据难以撤回；不能衡量证据数量与可靠性 |
| 真值与来源故障的联合后验 | 固定假设集下累积对数似然；在条件独立和精确算术假设下顺序无关；保留竞争解释 | 模型遗漏、相关或重复数据可导致虚假确信；删分支可恢复顺序依赖；假设集可能很大 |

根代理检查了对象映射、更新式和区分例子：两条路线在信息保留、重复证据处理和冲突能否消解上确实不同。回答还指出了浮点求和与固定比特内存的限制。它没有执行训练实验，也没有证明这些路线具有论文新颖性。

这次观察支持“能在这个问题上越过原型目录生成具体方案”，不支持“整体优于旧版”或固定的质量提升百分比。下一轮评估应冻结版本，对多个未见任务分别运行旧版与新版，并由不知道版本标签的评审比较迁移成立性、方向差异和研究价值；不能把答案出现某个数学名称当通过标准。

## 较早的构造与验证试用

在用户明确跨域探索优先级之前，还分别试用了“自回归模型自适应跳层”和“持续输入、可训练、自动停止的迭代状态”两个任务。文件名中的 `baseline` 是**上一轮维护修复后的快照**，不是已发布的原始 3.3.7；`after` 是本轮**构造工作流的中间版本**，不是最终跨域探索版本。试用时版本未完全冻结，完整临时 skill 复制已清理，不能据此作严格受控比较。

- 维护快照：[跳层回答](runs/baseline-answer.md)、[迭代回答](runs/baseline-iteration.md)、[CPU 汇总](runs/baseline-probe/summary.json)。已经能处理缓存、信息可得性、收缩与失败对照；132 个探测输入全部收敛。
- 构造中间版：[跳层回答](runs/after-answer.md)、[迭代回答](runs/after-iteration.md)、[CPU 汇总](runs/after-probe/iteration-results.json)。实际执行训练与停止检查，128 个测试输入均通过指定残差界检查；另检查无输入、非收缩与错误提前停止。

两版都完成了实质工作；其维度、合成目标、容差和训练设置不同，不能直接比较 MSE、步数或耗时来宣称 skill 改善。未执行 Transformer 训练或 GPU 测速。

从仓库根目录可复跑 CPU 代码（需 NumPy；第一份另需 Matplotlib；会重写相邻实验产物）：

```bash
python tests/usability/runs/baseline-probe/probe.py
python tests/usability/runs/after-probe/verify_iteration.py
python tests/usability/runs/after-probe/verify_skip_budget.py
```

归档保留原始中文回答和机器输出，不翻译实验记录。仅将两个回答中的执行命令改成当前相对路径；访问自报中的旧绝对路径是历史记录。重新运行后的耗时和浮点末位可能变化。
