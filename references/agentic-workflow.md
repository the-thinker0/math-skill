# Agentic 研究工作方式 / Human-in-the-Agent-Loop

> 提炼自一线 auto-research 实践（Infra / 算法 / 芯片 Co-design）。它定义本 skill 期望的**协作思维方式**：人做什么、Agent 做什么、用什么循环把"激发数学能力"落地。
> activator 在工作时引用本文件。This file defines the collaboration style the skill expects.

## 核心信条 / Creed

1. **这一次 AI 革命的数学基础，是 20 世纪数学第一次登上商用计算舞台**——范畴论、代数拓扑、代数几何。当前主流算法的数学基础大多还停留在 1800–1900 年代的微积分/线性代数。把现代数学激活进算法设计，是算法探索阶段最重要的事。
2. **谦卑**：模型预训练阶段的知识在广度上已超越任何个人。**更多是从模型里学知识，而不是教模型做事**。放下"教模型"的偏见，结果通常更好。
3. **数学美 ≠ 可算**：很多数学上很美的东西，遇到 GPU 并行与低精度误差就不能用。任何产出都要过 `gpu-friendly-math.md` 的验收门。

## 分工 / Division of Labor

**人负责（人类擅长、且最有价值的部分）：**
- **跨领域激活**：把一个领域的结构迁移到另一个领域。模型内部已有足够知识，但"没有人去激活它就很难被开发出来"。例：用代数几何观点研究模型结构；历史上纤维丛与规范场的对应——结构本就在那里，只差一次跨域激活。
- **不把主观偏见写死**：规则加得越多，越会限制模型探索更多可能。要好结果，**别把人的主观意愿硬塞进去**。
- **用模型扩大认知 context**：人脑同时手工比较的可变因子最多 2–3 个，模型的长上下文能同时权衡很多。借模型扩大个人认知的 context，是 agentic 开发的核心原则。
- **选方向、定验收门**：决定探索哪条路、用什么标准验收。

**Agent 负责（模型擅长的部分）：**
- **大上下文搜索与枚举**：枚举大量候选结构、并行比较多参数组合。
- **验证**：检验数学正确性 + GPU 可行性。
- **构建并执行 testplan**：把研究任务写成 markdown 表格追踪，自主新增 case、编译纠错、失败重试。

## 工作循环 / The Activation Loop

> activator 的 `诊断 → 映射 → GPU 筛选` 主流程就是这个循环的浓缩。

1. **诊断**：问题的算法结构 / 瓶颈是什么？（不要一上来堆数学科普。）
2. **跨域激活**：用 `books/*.md` 扫描可迁移的现代数学结构，**枚举多个候选**（发挥模型大上下文优势）。
3. **双验收门**：每个候选过两关——① 数学正确（区分定理、假设与启发式）；② 满足任务相关的工程约束。涉及 GPU 时按 `gpu-friendly-math.md` 评估相关维度，无关项标 `N/A`。
4. **迭代追踪**：用 markdown testplan 记录候选、评分、状态，逐步收敛。

## markdown testplan 模板 / Tracking Template

把研究任务写进一张可被 Agent 持续更新的表：

```markdown
| 候选结构 | 数学正确性 | 相关 GPU 维度 | 复杂度 | 状态 | 备注/下一步 |
|---------|-----------|---------|-------|------|-----------|
| 热带门控替代 TopK | [v] 可微松弛 | 1[v]2[x]3[v]… | 亚二次(逐token) | 验证中 | 对比 SWA 基线 |
| …            |           |         |       | 待办 |           |
```

Agent 负责追踪执行并更新此表；人负责读表、调方向。

## 原则清单 / Operating Principles

- **先诊断，再映射，最后筛选**——不做大段数学科普，直奔结构映射与 GPU 可行性。
- **保留探索自由**：少加硬规则，给模型留出探索空间。
- **人要"懒"**：把琐碎工作全交给 Agent，人只做跨域激活与方向判断。
- **渐进式披露**：方法论层、GPU 清单、书籍层都按需加载，常驻只留最短的触发与诊断逻辑，省 token。
- **不要一来就造一堆 skill / 规则**：模型本身已有很多能力，先用足，再补结构。
