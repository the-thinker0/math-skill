# 多轮研究：根据证据修改候选

仅在需要持续构造、比较方案或推进实验时读取。主入口为 `../SKILL.md`；首次从模糊目标构造机制时读 [构造工作台](design-workbench.md)，不需要每轮重读。

## 复用已经确定的部分

从当前对话或用户已有笔记恢复：研究目标与硬约束；候选的核心式；已经核验的条件；失败过的反例；实际测量结果。本轮先指出哪一个新事实需要处理，不重列透镜、书目和全部候选。

用户的“继续”“这个实验失败了”“换个思路”通常是在推进原目标。只有目标或约束确实改变时才重新形式化。

## 把最关键的不确定性变成一个检查

优先选择结果会改变设计的检查。例如：

| 当前未知 | 有区分力的检查 | 结果如何改变方案 |
|---|---|---|
| 一致性目标是否把表示压成常数 | 让常数解与保留输入的解在小数据上竞争，分别检查目标和任务信息 | 若常数解胜出，改变约束/数据项后重新比较 |
| 近似误差是否被后续层放大 | 固定同量级局部误差，改变后续算子的敏感方向 | 若显著放大，转向输出相关误差或改变预算分配 |
| 随机残差是否真的值得计算 | 相同总成本下比较纯近似、直接抽样与残差修正 | 若残差更不稳定，修改基线或放弃该组合 |
| 迭代状态是否可可靠早停 | 对比解析解与残差阈值，再破坏收缩条件 | 若条件被破坏，修订参数化或撤回该停止保证 |

用户已要求实现/验证且环境可执行时，编写并运行当前候选的小探针，记录命令、输入、观测值和判定。失败后修订关键点并重跑相关检查；不要只重复一段“下一步实验建议”。缺少数据或计算条件时，给可运行实现和判定标准，明确未执行的部分。

## 根据结果推进

- **性质被推翻**：保留反例；优先修正所依赖的假设、参数化或目标，不靠移动阈值把它变成通过。
- **性质仅在小对象成立**：记录适用范围，再迁移到独立数据与真实实现；有限检查不是全称证明。
- **质量成立、资源收益不成立**：分别测预处理、前向/反向或 prefill/decode、状态存储和动态 batch 开销，决定保留机制还是简化实现。
- **达到用户接受标准**：给最终方案与证据，停止无必要的候选扩张。

数学定义正确、推导成立、有限数值支持、实测任务收益是不同状态。“计划”“尚未运行”“失败”应原样记录，不能升级为成功结果。

## 需要留档时的最小状态

优先更新用户已有研究记录；用户要求保存或任务已在维护实验文件时，可保留下面这些信息，不强制新建表格或新目录：

> 目标/约束 → 当前候选与核心式 → 条件及来源 → 已运行的检查与结果 → 已淘汰路径及原因 → 下一项会改变选择的检查。

下轮只处理状态的变化。发现新方法、精确常数或新颖性问题时再核验一手来源，不把“已核验一个定理”扩展为“整个迁移方案已被证明”。
